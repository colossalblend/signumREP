# Хранение данных Signum

Бот и API запускаются одним процессом на российском хостинге. IPA хранятся отдельно на зарубежном VPS.

## Российский хостинг

Приватная папка: `/var/www/u3614956/data/signum-private`, вне публичного `/www/signum.appbank.pw`.

- `control/data/signum.db`: SQLCipher, включая пользователей, квоты, платежи и API-аккаунты.
- `control/data/accounts/*/.store-session.enc`: зашифрованные Apple-сессии.
- `control/data/*.session.enc`: зашифрованные Telegram-сессии.
- `control/data/backups`: зашифрованные резервные копии базы.
- `control/data/logs`: журналы с шифрованием каждой строки; heartbeat содержит только состояние процесса.
- `keys/database.key` и `keys/session.key`: ключи вне папки данных; хранить отдельно от резервной копии.
- `control/.env`: рабочие секреты, доступ только владельцу.

Папки имеют права 700, приватные файлы 600. Сессии расшифровываются только в `/dev/shm` и удаляются после использования. Копии ключей необходимы для восстановления: утрата ключей делает данные недоступными. Доступ к аккаунту хостинга позволяет прочитать ключи, поэтому шифрование не заменяет защиту FTP и панели хостинга.

## Запуск и восстановление

`control/bin/python control/hosting-watchdog.py` проверяет heartbeat и запускает отсутствующий процесс. Cron запускает watchdog каждую минуту. Файл `control/DISABLED` запрещает автоматический запуск.

В конфигурации включены `SESSION_ENCRYPTION=1`, `API_EMBEDDED=1`, `BRIDGE_IN_PROCESS=1`; пути к ключам заданы через `SIGNUM_DB_KEY_FILE` и `SIGNUM_SESSION_KEY_FILE`.

На хостинге используется переносимый Python и bundled glibc. Все native Apple-команды используют исходники Sorvigolova/ipatool 1.1.1 без изменений в авторизации и выборе MAC. Переменная `IPATOOL_MAC` удалена; устройство выбирает сам ipatool. Обёртки libcurl задают CA-файл и загружают `runtime/curl-ca-bridge.so`, собранную из `native_store/curl_ca_bridge.c` (`gcc -shared -fPIC -Wall -Werror -ldl`). Проверка TLS обязательна.

## Зарубежный VPS

Служба `signum-objects` хранит IPA в `/var/lib/signum-objects`. Метаданные содержат только случайный идентификатор, размер и срок удаления. Российский PHP-мост передаёт файл потоком без постоянной копии IPA.

Telegram-транспорт передаёт непрозрачный MTProto-трафик по авторизованному TLS WebSocket. Сессии и база на VPS не сохраняются. Доступ ограничен адресами Telegram, подписанными запросами и защитой от повторного использования подписи.

## Обновление моста

`tools/deploy_bridge.py` сохраняет существующий приватный `config.php`, включая настройки объектного хранилища. При несовпадении ключа или домена обновление останавливается. Временный исполнитель `hosting_task` в рабочем мосте отсутствует.

Перенос хранения не является полной проверкой требований 152-ФЗ: отдельно учитываются обмен с Apple/Telegram и возможные персональные метаданные внутри IPA.
