# Signum Bot

Телеграм-бот поверх `ipatool`: находит приложение, качает IPA с вашего Apple ID и
либо присылает файл в чат, либо отдаёт ссылку с `.plist` для установки прямо на
iPhone.

```
signum_bot/
  config.py    настройки из .env
  db.py        SQLite: пользователи, Apple ID, приложения, файлы, история, платежи
  ipatool.py   обёртка над бинарником (свой HOME на каждый Apple ID)
  store.py     метаданные: каталог Signum + iTunes API
  ota.py       .plist-манифест, страница установки, раздача файлов, уборка
  ui.py        тексты и клавиатуры
  handlers.py  сценарии бота
tests/test_bot.py   самопроверка: python tests/test_bot.py
```

## Что умеет

| Экран | Откуда данные |
|---|---|
| 📚 Каталог | `api.appbank.pw/signum` — приложения банков, которых нет в App Store |
| 🔎 Поиск | iTunes Search API (название, bundle id или ссылка на App Store) |
| ◷ Другие версии | старые сборки Apple из карточки приложения; выбранный ID передаётся в загрузку |
| 🧾 История покупок | модули Apple из Signum, страницы и кеш; работает с ipatool 1.0.7 |
| 📥 Мои загрузки | история пользователя, любое можно скачать повторно |
| 🍏 Мой Apple ID | подключение, история покупок, страна App Store и смена страны |
| 💎 Подписка | лимиты и оплата |
| 🛠 Админ-панель | видна только тем, кто в `BOT_ADMINS` |

Выдача: **📥 .ipa** — файлом в чат или **📲 Установить** — страница в Safari
с кнопкой `itms-services://`.

При открытии приложения каталога бот проверяет покупки подключённого Apple ID,
как Signum: `list-versions` для каждого уникального App Store ID, с проверкой
конкретного `external_version_id`, когда он задан. В список попадают только
подтверждённые приложения и сборки. Ответы сохраняются в SQLite: покупки на
24 часа, подтверждённое отсутствие покупки на час, отдельно для
каждого аккаунта и сессии; кнопка «Обновить покупки» сбрасывает проверку.
Без подключённого Apple ID предлагается вход. Ошибки Apple и пустые ответы при
сломанных Store cookies показываются как непроверенные, а не «нет в покупках».

## Размеры

| | Потолок приложения | Как приходит |
|---|---|---|
| бесплатно | `MAX_MB_FREE` — 2 ГБ | файлом в чат |
| по подписке / за разовую оплату | `MAX_MB_SUB` — 4 ГБ | файлом через Premium-отправителя или кнопкой скачивания |

Логика бота — на **aiogram**, сами файлы уходят через **Telethon** по MTProto:
Bot API отдаёт документом жалкие 50 МБ, MTProto тем же ботом — до 2 ГБ. Нужны
ключи с [my.telegram.org](https://my.telegram.org) в `TG_API_ID` и `TG_API_HASH`.

`MTPROTO_MAX_MB` ограничивает отправку, но не повышает лимит Telegram. Для
передачи до 4 ГБ нужен отдельный личный аккаунт с Telegram Premium: обычный
бот остаётся отправителем небольших файлов. Если большой файл не проходит
в Telegram, бот выдаёт кнопку скачивания при настроенном `PUBLIC_BASE_URL`.
Прямая отправка ограничена серверным потолком: 2000/4000 МиБ. Файл,
отправленный в чат, удаляется с диска. Бесплатная ссылка живёт 1 час
(`LINK_TTL_FREE_HOURS`), по подписке или за разовую оплату — 12 часов
(`LINK_TTL_PAID_HOURS`). Срок фиксируется при выдаче и проверяется при каждом
обращении к странице, манифесту и файлу; смена тарифа его не изменяет.

### Подключение личного Premium-аккаунта

Запустите локально из папки `bot`:

```powershell
python tools/connect_premium.py --create-relay
```

На телефоне: **Telegram → Настройки → Устройства → Подключить устройство**.
Отсканируйте открывшийся QR-код. Если включён облачный пароль, введите его в
локальном терминале. Для входа по номеру и коду добавьте `--phone`.

Скрипт проверяет Premium, создаёт закрытый служебный канал и назначает бота
администратором. Сохраняет сессию в `data/premium-upload.session`, а в `.env`
записывает `TG_PREMIUM_SESSION`, `TG_UPLOAD_RELAY` и `MTPROTO_MAX_MB=4000`.
Существующий канал можно указать через `--relay -100...`. Повторный запуск
использует сохранённую сессию и канал. Перезапуск на Windows:

```powershell
powershell -ExecutionPolicy Bypass -File tools/start_bot.ps1 -Restart
```

Файл больше 2 ГБ загружает Premium-аккаунт в канал; бот копирует сообщение
получателю без ссылки на личный аккаунт. Временное сообщение в канале удаляется.
Сессия остаётся локально, не попадает в Git. Если Premium истёк, загрузка
через него прекращается. Бесплатные установки сохраняют свой лимит 2 ГБ.

## Лимиты и оплата

- бесплатно `FREE_PER_WEEK` (по умолчанию 3) приложения в неделю;
- разовая установка — `PRICE_SINGLE` (29 ₽);
- подписка на 7 / 30 / 180 / 365 дней — без ограничений.
- подписчикам — фоновый прогрев KBSync для всех подключённых рабочих Apple ID
  раз в 12 часов, чтобы готовить старт загрузки заранее.

Прогрев выполняется внутри процесса бота, начиная с запуска. Новая подписка
или подключённый Apple ID подхватываются при следующем проходе (раз в минуту).
Занятые аккаунты пропускаются до следующего прохода; одновременно выполняется
один прогрев. После ошибки повтор — через 15 минут. Успешное время хранится в
SQLite и переживает перезапуск. После окончания подписки, блокировки или
отключения Apple ID фоновая обработка прекращается. Первый прогрев всё ещё
занимает время; скорость передачи файла зависит от Apple и Telegram.

## Движок и оформление

Администратор может отправить боту любой текст с custom emoji: бот вернёт тот
же текст, заменив каждую такую иконку её `custom_emoji_id`. Обычные эмодзи,
переносы строк и остальной текст сохраняются. Работают текст и подпись к фото;
для длинного результата бот отдаёт целый `.txt`. Команда `/emoji` показывает
подсказку. Замена кнопок автоматически не выполняется: результат можно
использовать в следующем запросе на оформление. Вход в Apple ID и рассылка
не перехватываются извлекателем.

Выбранные ID для меню, приложений, навигации и цифр сохранены в
`signum_bot/assets/button-emojis.json`. Оформление применяется к клавиатурам
при отправке, включая новые сообщения и обновление существующих. Указанный
ID сохраняется точно: статичный значок не превращается в анимированный.
Если Telegram запрещает custom emoji для бота, сообщение повторяется
с обычными значками.

По умолчанию `IPATOOL_ENGINE=v6`: используется C++ CLI
[Sorvigolova/ipatool 1.0.7](https://github.com/Sorvigolova/ipatool/releases/tag/1.0.7).
В текущем Signum бинарник этой версии лежит в каталогах с именем `v5`; настройки
`v5` и `v6` в основном приложении ссылаются на этот же бинарник. Бот использует
CLI 1.0.7, включая `auth info`, `list-versions` и `kbsync --refresh`; специальные
настройки идентичности из Rust-клиента Signum сюда не перенесены.

Укажите `IPATOOL` явно или оставьте пустым для поиска бинарника в соседнем Signum.
Для старого Go-бинарника нужен `IPATOOL_ENGINE=go`; фоновый KBSync ему недоступен.
После перехода с Go может потребоваться повторный вход в Apple ID из-за другого
формата сессии. Деплой копирует Linux CLI 1.0.7 из `bin/ipatool` либо соседнего
Signum; старый Go CLI автоматически не подставляется.

Обложки и карточки используют палитру и логотип Signum. Логотип включён в
`signum_bot/assets/signum.png`, поэтому на сервере папка основного приложения
для оформления не нужна. Кнопки ведут к старым версиям, новому поиску и главному
меню; переходы поддерживают сообщения с фотографиями. `cachetools` ограничивает
размер и время жизни кешей метаданных, карточек и результатов поиска.

Проверка и предпросмотр без подключения к Telegram:

```powershell
python tests/test_bot.py
python tests/test_refresh.py
python tests/test_ownership.py
python tools/preview_design.py
```

Последняя команда сохраняет примеры в `design-preview/`; названия и версии
приложений в них демонстрационные.

Тарифы в рублях: 29 ₽ за установку, 79 ₽ за 7 дней, 199 ₽ за 30 дней,
899 ₽ за 180 дней, 1490 ₽ за год. Цены меняются через `PRICE_*` в `.env`.
При `PAYMENT_MODE=demo` покупка показывает сумму и кнопку демоактивации:
деньги не списываются. Повторное подтверждение заказа не начисляет тариф
второй раз; заказ действует час и привязан к своему Telegram ID.
Демооперации записываются отдельно и исключаются из реальной выручки.
Stars не используются. `PAYMENT_MODE=yookassa` включает ЮKassa:
При `BRIDGE_ENABLED=1` создание платежей и проверка статуса идут через
фиксированный адрес ЮKassa на хостинге. Запросы и ответы зашифрованы AES-GCM;
секрет магазина не записывается на хостинге. Мост проверяет подпись и повторные
запросы, разрешает только создание платежа и чтение его статуса. Это позволяет
работать при недоступности ЮKassa с VPS. Без моста используется прямое соединение.
`YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RETURN_URL` задаются в `.env`.
Ключ `test_*` включает тестовый магазин. Кнопка открывает защищённую оплату;
«Проверить оплату» получает статус прямо у ЮKassa. Сумма, валюта, магазин,
метаданные заказа и тестовый режим сверяются до начисления. Повторная проверка
и повторные уведомления не начисляют покупку дважды. Тестовые платежи исключены
из реальной выручки. Карта не сохраняется; автопродления нет.

Для уведомлений укажите `https://PUBLIC_HOST/payments/yookassa` в кабинете ЮKassa,
события `payment.succeeded`, `payment.canceled`. Если сервер доступен только по
локальному IP, ЮKassa не сможет прислать уведомление: бот также проверяет
незавершённые платежи каждые 30 секунд, поэтому начисление работает без webhook.
Уведомление служит только поводом проверить платёж через API провайдера.
После подтверждения настоящей оплаты бот отправляет администраторам из
`ADMINS` имя и Telegram ID покупателя, тариф, сумму и номер платежа.
Очередь уведомлений сохраняется вместе с начислением покупки и переживает
перезапуски. Повторная проверка платежа не создаёт новое уведомление;
тестовые и демопокупки уведомлений об успешной оплате не отправляют.

## API для клиентов

API покупается отдельно: 299 ₽ за 30 дней и 1000 загрузок; обычная подписка
не открывает API. Доступен из главного меню, раздела подписки или команды `/api`.
Активируйте API и создайте ключ в разделе «Мои ключи». Подключить Apple ID
можно через API или панель `/api/panel`, независимо от Telegram. Можно хранить
несколько аккаунтов и ключей. Секрет каждого ключа выдаётся один раз.
В базе хранится только SHA-256 ключа. Кнопка отключения сразу отзывает его.

Страница с примерами и проверкой ключа: `GET /api/docs`;
машинное описание: `GET /api/schema.json`. Авторизация: `Authorization: Bearer sg_...`.
Ключ истекает через 30 дней (`API_KEY_DAYS`); можно создать ключ только для
чтения. Для внешнего подключения требуется HTTPS. API ограничивает перебор
ключей по IP, частоту запросов по клиенту и одновременные запросы (не более 3).
`GET /api/v1/me` — срок доступа и остаток загрузок;
`GET /api/v1/catalog` — список приложений;
`GET /api/v1/catalog/{slug}` — сборки, доступные подключённому Apple ID;
`GET /api/v1/search?q=...` — поиск;
`GET /api/v1/apps/{adam_id}` — метаданные;
`GET /api/v1/apps/{adam_id}/versions` — доступные версии.

```bash
curl -H 'Authorization: Bearer sg_YOUR_KEY' \
  -H 'Idempotency-Key: download-001' \
  -H 'Content-Type: application/json' \
  -d '{"adam_id":"123456","kind":"ipa"}' \
  https://YOUR_HOST/api/v1/downloads
curl -H 'Authorization: Bearer sg_YOUR_KEY' \
  https://YOUR_HOST/api/v1/downloads/JOB_ID
```

`POST /api/v1/downloads` принимает `adam_id`, `kind` (`ipa` или `ota`) и
необязательный `version_id`. Возвращает `job_id`; запрос статуса возвращает
`file_url`, а для OTA — также `install_url`, `manifest_url`, `itms_services_url`.
Последняя содержит готовый переход iPhone в системную установку. `Idempotency-Key`
обязателен: повтор одного запроса не расходует лимит дважды. Файл до 4 ГБ,
ссылка на 12 часов; лимиты `MAX_MB_SUB`, `LINK_TTL_PAID_HOURS` общие с ботом.
30 запросов в минуту (`API_RATE_LIMIT`), одна активная загрузка на клиента,
до 10 задач в общей очереди. Ошибка или перезапуск возвращают загрузку в баланс.
После истечения срока API ключ не работает. Новая покупка активного API
добавляет 30 дней и 1000 загрузок; покупка после истечения даёт новый пакет.
Бесплатный лимит бота и кредиты API учитываются отдельно. Общего лимита в ГБ нет.
Дополнительные пакеты: 100 загрузок за 49 ₽, 500 за 149 ₽, 1000 за 249 ₽.
Они не продлевают API; остаток сохраняется даже после окончания доступа.
Для использования нужно продлить API. Сначала расходуется основной пакет,
затем дополнительные загрузки. Ошибка возвращает лимит в исходный баланс.
`/me` возвращает `downloads_remaining`, `package_downloads_remaining`,
`extra_downloads_remaining`. Пополнить можно в боте или через API:
`GET /api/v1/billing/packages`, `POST /api/v1/billing/orders` (JSON `plan=api500`,
заголовок `Idempotency-Key`), `GET /api/v1/billing/orders/{order_id}`.
Ответ заказа содержит `payment_url`. Создание заказа требует права `billing`;
для старых ключей получите новый полный ключ в боте.
`DELETE /api/v1/downloads/{job_id}` отменяет и возвращает резерв активной задачи
или отзывает готовые ссылки; уже выданный файл при отзыве не возвращает лимиты.
Ссылки истекают автоматически. На выдачу IPA действует ограничение параллельных
скачиваний: до 3 на IP и до 12 суммарно.

Ручная выдача админом: `/grant <tg_id> 30` (дни подписки) или `/grant <tg_id> +5`
(разовые установки).

## Apple ID

Аккаунт подключает **сам пользователь**: `🍏 Мой Apple ID → ➕ Подключить`.
Мастер в три шага спрашивает почту, пароль и, если Apple попросит, код
проверки. Сообщения с паролем и кодом бот удаляет из чата сразу. Дальше
приложения качаются с его аккаунта — как если бы человек нажал «Загрузить» в
App Store. Отключить — одной кнопкой.

Каждый Apple ID живёт в своём `HOME` (`data/accounts/<id>`): ipatool держит
сессию в keychain внутри домашней папки, поэтому аккаунты не затирают друг
друга.

## Админ-панель

Кнопка **🛠 Админ-панель** появляется в `/start` только у тех, чей id есть в
`BOT_ADMINS` — остальные её не видят, а колбэки всё равно проверяются на
сервере. Внутри: сводка (люди, Apple ID, выдачи, место на диске, оплаты),
список пользователей с выдачей подписки/установок и блокировкой, все
подключённые Apple ID, уборка файлов и рассылка с предпросмотром.

```
/admin                          панель
/apple                          мой Apple ID
/grant tg_id 30                 подписка на 30 дней
/grant tg_id +5                 пять разовых установок
```

## Установка на Ubuntu

```bash
scp -r bot/ root@server:/root/signum-bot-src
ssh root@server 'cd /root/signum-bot-src && bash deploy.sh'
nano /opt/signum-bot/.env      # BOT_TOKEN, BOT_ADMINS, PUBLIC_BASE_URL
systemctl restart signum-bot
```

`ipatool` положите в `/opt/signum-bot/bin/ipatool` (в этом репозитории готовый
linux-бинарник 1.0.7 лежит в `linux_x64/ipatool-v5`; копия включена в `bot/bin/ipatool`) либо передайте `IPATOOL_URL=...`
скрипту деплоя.

Nginx перед ботом — **обязательно с валидным HTTPS**, иначе iOS откажется
ставить приложение по `itms-services`:

```nginx
server {
    server_name bot.example.com;
    client_max_body_size 0;
    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_buffering off;          # IPA отдаются потоком
    }
}
```

```bash
certbot --nginx -d bot.example.com
```

## Про подпись

App Store-сборка зашифрована под тот Apple ID, который её купил. Ссылка `.ipa`
работает всегда, а установка по воздуху надёжно проходит только для подписанной
сборки. Если на сервере есть `zsign` и сертификат — пропишите `ZSIGN`,
`ZSIGN_CERT`, `ZSIGN_KEY`/`ZSIGN_PASSWORD`, `ZSIGN_PROV`, и бот подпишет IPA
перед выдачей манифеста. Без этих переменных шаг просто пропускается.


## Управление API и вход без Telegram

Подробный контракт входа, 2FA, ключей и лимитов: [docs/api.md](docs/api.md).
Админка: «API и ключи» → клиент → баланс, срок или ключи. В панели `/api/panel`
можно подключить несколько Apple ID, создать и приостановить ключи, изменить
их лимиты и пополнить загрузки. API-аккаунты изолированы от аккаунтов бота.
При нескольких готовых аккаунтах передавайте `account_id`.

Отдельный процесс API: `API_EMBEDDED=0`, затем `python -m signum_bot.api_server`.
Токен Telegram не требуется. Windows: `powershell -File tools/start_api.ps1`.
API продолжает работать при перезапуске бота. Два API-процесса для одной базы
не допускаются. Конфигурация внешней защиты: `deploy/nginx-api.conf`.


История покупок и смена страны: [описание помощника Apple](apple_bridge/README.md).
Кнопки доступны в «Мой Apple ID»; история также открывается командой `/purchases`.
