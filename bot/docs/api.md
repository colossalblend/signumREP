# Signum API

Панель: `/api/panel`. Примеры: `/api/docs`. Все методы ниже начинаются с `/api/v1`.
Передавайте `Authorization: Bearer sg_…`. Внешние подключения работают по HTTPS.
Почта, пароль и код передаются только в JSON, никогда в адресе запроса.

## Вход в Apple ID

Вход работает без Telegram. API хранит свои аккаунты отдельно от аккаунтов бота.
Можно подключить до 10 Apple ID на клиента. Аккаунты разных клиентов изолированы,
в том числе при совпадении почты. Пароли в базе зашифрованы; ключ шифрования
находится отдельно в `data/secrets/apple-api.key`. Коды 2FA в базу не записываются.

1. `POST /auth/jobs`, право `accounts`, уникальный `Idempotency-Key` (8–128 символов):

```json
{"email":"you@example.com","password":"YOUR_PASSWORD"}
```

Ответ `202` приходит сразу:

```json
{
  "job_id":"RANDOM_LOGIN_JOB",
  "status":"queued",
  "message":"Вход ожидает очереди.",
  "action":"poll",
  "expires_at":1790000600,
  "poll_after_seconds":5,
  "error":null
}
```

2. `GET /auth/jobs/{job_id}`, с тем же API-ключом. Опрос раз в 5 секунд.
Статусы: `queued`, `authenticating`, `requires_2fa`, `verifying_2fa`, `ready`,
`failed`, `expired`, `canceled`. Поле `action` подсказывает следующее действие.
Если аккаунт уже подключён, повторный запрос вернёт `ready` без повторного входа.

Успешный вход без 2FA:

```json
{
  "job_id":"RANDOM_LOGIN_JOB",
  "status":"ready",
  "message":"Apple ID подключён.",
  "action":"none",
  "account_id":"RANDOM_ACCOUNT_ID",
  "expires_at":1790000600,
  "poll_after_seconds":null,
  "error":null
}
```

Если Apple запросил подтверждение:

```json
{
  "job_id":"RANDOM_LOGIN_JOB",
  "status":"requires_2fa",
  "message":"Введите 6 цифр кода с устройства Apple или из SMS.",
  "action":"submit_2fa_code",
  "challenge_token":"RANDOM_CHALLENGE_TOKEN",
  "code_url":"/api/v1/auth/jobs/RANDOM_LOGIN_JOB/code",
  "attempts_remaining":3,
  "expires_at":1790000600,
  "poll_after_seconds":5,
  "error":null
}
```

3. Только при `requires_2fa`: `POST /auth/jobs/{job_id}/code`:

```json
{"code":"123456","challenge_token":"RANDOM_CHALLENGE_TOKEN"}
```

Ответ `202`, статус `verifying_2fa`. Продолжайте опрашивать задачу. При неверном
коде вернётся `requires_2fa`, ошибка `invalid_2fa_code` и новый `challenge_token`.
Старый токен повторно не принимается. После 3 отправленных кодов задача завершится
с `too_many_2fa_attempts`. Код без запроса 2FA — `409 code_not_required`.

Задача живёт 10 минут, включая ожидание очереди и кода. После перезапуска сервиса
незавершённый вход получает `expired / restart_login`: начните новый запрос.
Один клиент может иметь до 2 незавершённых входов, глобальная очередь — до 32.
До 10 новых попыток входа в час; повтор с тем же ключом идемпотентности не создаёт
ещё одну задачу. Изменение почты, пароля или API-ключа с прежним Idempotency-Key
возвращает `409 idempotency_conflict`. Ошибки не содержат пароль и вывод ipatool.

`DELETE /auth/jobs/{job_id}` отменяет незавершённый вход.
`GET /accounts` показывает `account_id`, почту, статус и дату добавления.
`GET /accounts/{account_id}` показывает один аккаунт.
`DELETE /accounts/{account_id}` отключает аккаунт и удаляет его сессию;
во время загрузки вернётся `409 account_busy`.

## Выбор аккаунта и загрузка

Для нескольких подключённых Apple ID передавайте `account_id`:

```json
{"adam_id":"123456789","kind":"ota","account_id":"RANDOM_ACCOUNT_ID"}
```

`POST /downloads` требует `downloads` и `Idempotency-Key`. Варианты `kind`:
`ipa` — файл, `ota` — файл и установка iPhone. Если готовых аккаунтов несколько,
а `account_id` отсутствует, вернётся `409 account_selection_required`.
Для старых клиентов сохранена совместимость с аккаунтом, подключённым через бота.
У `/apps/{adam_id}/versions` и `/catalog/{slug}` выбор аккаунта — параметр запроса
`?account_id=…`. Аккаунт другого клиента даёт `404 account_not_found`.

`GET /downloads/{job_id}` возвращает статус и после подготовки:

```json
{
  "job_id":"RANDOM_DOWNLOAD_JOB",
  "status":"ready",
  "error":null,
  "file_url":"https://YOUR_HOST/f/RANDOM_TOKEN.ipa",
  "install_url":"https://YOUR_HOST/i/RANDOM_TOKEN",
  "manifest_url":"https://YOUR_HOST/ota/RANDOM_TOKEN.plist",
  "itms_services_url":"itms-services://?action=download-manifest&url=https%3A%2F%2FYOUR_HOST%2Fota%2FRANDOM_TOKEN.plist",
  "expires_at":1790043200,
  "title":"Приложение",
  "size":467455180
}
```

Поля установки появляются только для `kind=ota`. Ссылки действуют 12 часов.
`DELETE /downloads/{job_id}` отменяет загрузку или отзывает готовые ссылки.
Ошибка и отмена возвращают резерв в исходные балансы клиента и ключа ровно один раз.
Отзыв готового файла не возвращает уже использованную загрузку.

## Ключи и квота

`GET /keys` возвращает список без секретов и хешей, `current_key_id` — текущий ключ.
До 20 неотозванных ключей на клиента. Состояния: `active`, `paused`, `revoked`.
Отозванный ключ восстановить нельзя. Полный набор прав: `read`, `downloads`,
`accounts`, `billing`, `keys`. Ключ с `read` может только просматривать данные.

`POST /keys` требует `keys` и ключ без отдельного лимита:

```json
{"label":"Мой сайт","scopes":["read","downloads","accounts"],"days":30,"quota":100}
```

Ответ `201`: `key_id`, `api_key`, пояснение о сохранении секрета. Секрет показывается
один раз. В базе хранится SHA-256. Права нового ключа не могут превышать права
создателя; срок не превышает срок текущего ключа. Создание ключа не пополняет баланс.

`PATCH /keys/{key_id}` изменяет поля:

```json
{"state":"paused","quota_remaining":50,"expires_at":1790000600,"label":"Новый сайт"}
```

Можно передать только нужные поля. `quota_remaining=null` означает общий баланс,
`0` запрещает новые загрузки по ключу. Отдельная квота ключа расходуется вместе
с общей квотой клиента, а не вместо неё. Ограниченный ключ не может создавать,
менять или отзывать ключи. `DELETE /keys/{key_id}` безвозвратно отзывает ключ.

Администратор в боте может изменять баланс клиента, срок API, состояние и лимиты
любого его ключа. Изменения записываются в историю без секретов и паролей.

`GET /me` возвращает срок API, общий остаток, основные и докупленные загрузки,
права текущего ключа, его срок и квоту, количество подключённых Apple ID.
Основной пакет: 1000 загрузок за 299 ₽ / 30 дней. Общего лимита в ГБ нет.
Пополнение: `GET /billing/packages`, `POST /billing/orders`,
`GET /billing/orders/{order_id}`. Подробности — на странице `/api/docs`.

## Ограничения нагрузки

По умолчанию: 30 запросов в минуту на клиента (общие для всех его ключей),
120 запросов в минуту на IP, 1200 в минуту на весь API. До 3 активных запросов
на клиента и 32 суммарно. При превышении — `429`, `Retry-After: 60`; при общей
перегрузке — `503 server_busy`. Размер тела API — до 4 КБ, обработка запроса
ограничена 60 секундами. До 1 активной загрузки на клиента, до 10 в очереди.
На выдаче файлов: до 3 соединений с IP, до 12 суммарно.

Нельзя передавать ключ через URL. Заголовки реального IP учитываются только от
явно доверенного прокси (`API_TRUSTED_PROXIES`); остальные игнорируются.
В `deploy/nginx-api.conf` есть ограничения частоты, соединений и времени чтения
на входе. Конфигурацию нужно применить на публичном сервере; она не включается
автоматически при запуске Python. Защита от заполнения интернет-канала требует
внешней защиты на стороне хостинга.

## Запуск без бота

Для отдельного API установите `API_EMBEDDED=0` у бота и запустите:

```powershell
python -m signum_bot.api_server
```

API не требует `BOT_TOKEN`, Telegram-сессии и подключения к Telegram.
В Windows скрытый запуск: `powershell -File tools/start_api.ps1`.
Повторный API-процесс для той же базы блокируется, чтобы задачи не мешали друг другу.
Перезапуск бота не останавливает отдельный API.

Создать клиента без Telegram можно из локального терминала администратора:

```powershell
python -m signum_bot.api_admin --name "Мой клиент" --days 30 --downloads 1000
```

Команда выдаст ID клиента и новый секретный ключ. Ключ сохраняйте отдельно;
в браузерных снимках, логах и открытом коде сайта ему места нет.
