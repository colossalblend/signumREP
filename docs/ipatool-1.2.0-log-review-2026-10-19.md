# ipatool 1.2.0 и разбор логов — 19 октября 2026

Проверены все 10 переданных файлов: восемь batch-файлов за 15–19 октября и два support JSON за 17 октября. Всего 26 399 строк; batch-файлы могут содержать повторные сессии, поэтому число строк ошибок не равно числу пользователей или отдельных сбоев.

## Изменения

- Встроенный ipatool-cpp обновлён с 1.1.8 до [релиза 1.2.0](https://github.com/Sorvigolova/ipatool/releases/tag/1.2.0) для Windows x64, macOS Intel/Apple Silicon и Linux x64. Linux ARM64 отсутствует среди артефактов upstream; его существующий движок сохранён.
- Все архивы сверены с SHA-256 в метаданных релиза GitHub. Обновлены SOURCE.json, версия KBSync и разрешённые хеши macOS. Старый управляемый движок не перекроет новый встроенный.
- Подготовлены backend/signum/files/tools/*/ipatool-v5-1.2.0 и манифест с размерами и SHA-256. Остальные записи манифеста и старые файлы сохранены. На сервер ничего не отправлялось.
- Исправлен вызов `list-versions -i ""`: пустая строка ошибочно проходила проверку `all(is_ascii_digit)`. Единая нормализация теперь используется также при покупке, скачивании и формировании ключей кэша. При отсутствующем ID выбирается Bundle ID; пробелы вокруг числового ID удаляются.
- Ответ `you must purchase this app first` распознаётся как отсутствие лицензии. Раньше он оставался неопределённым результатом и вызывал повторные запросы к тем же приложениям. Ошибки входа и сети по-прежнему не означают отсутствия покупки.

## Что показали логи

| Сообщение / сценарий | Вывод |
| --- | --- |
| `Usage: ipatool list-versions ...` и пустой `-i` | Исправлено в этом изменении. |
| `you must purchase this app first` | Исправлено распознавание ответа и возможность кэширования отрицательного результата. Покупки не добавляются автоматически во время проверки истории. |
| `minizip: failed to open output IPA for append` | В переданном Windows support-логе использовалась папка назначения. В текущем рабочем коде уже есть отдельная временная папка, явный `download.ipa`, короткий Windows-путь и однократный повтор упаковки. Эти исправления сохранены; обновление upstream само по себе не подтверждает устранение minizip. |
| `Enter 2FA code ... Login failed after retry` | Текущий код распознаёт это как запрос 2FA; следующие строки логов подтверждают переход на ввод кода. |
| `cannot load cookies: invalid character '#'` | Связано с разными форматами cookie у Go и C++ движков. В рабочем коде уже есть распознавание libcurl-cookie и сохранение/восстановление cookie при проверке другого движка. |
| `Unknown command: warm-kbsync` | В текущем коде используется поддерживаемая команда `kbsync`; старый вызов встречается в записанных сессиях. |
| `Bad CPU type in executable` | Встречается в старых macOS-сессиях. Проверены заголовки текущих ideviceinfo, idevicepair, ideviceinstaller и zsign: Intel-файлы имеют x86_64, Apple Silicon — arm64. Запуск на Mac в этой проверке не выполнялся. |
| `account is disabled`, `item is temporarily unavailable`, DNS/TLS/HTTP-сбои Apple | Внешние причины; нельзя объявлять исправленными заменой бинарника. |

## Проверки

- SHA-256 и размеры новых встроенных и серверных бинарников совпадают с манифестом на всех четырёх платформах.
- Windows CLI запущен с отдельным пустым профилем: `auth info` корректно отвечает `Not logged in` без доступа к рабочей сессии.
- Добавлены регрессионные проверки пустого/невалидного ID, нормализации ID и текста отсутствующей лицензии.
- `cargo test --manifest-path src-tauri/Cargo.toml --bin signum -- --test-threads=2`: 130 пройдено, 0 ошибок, 2 live-теста с Apple ID пропущены штатно. В том числе прошли проверки minizip-повтора, cookie, 2FA и новых ошибок из логов.
- `npm run build`: TypeScript, Vite и обфускация завершились успешно. Остались предупреждения о неиспользуемом Rust-коде и размере JS-чанка.
- `git diff --check` для изменённого Rust-кода и скрипта: без ошибок.

Резервные копии заменённых бинарников и манифеста: `tmp/ipatool-release-1.2.0/previous/`. Полный вход в Apple ID, скачивание через Apple и установка на iPhone в рамках этой проверки не выполнялись. Исходные логи с данными пользователей в отчёт не скопированы.
