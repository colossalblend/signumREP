## 1. Коротко: почему SpeakaBoo «не качается»

СберKids в магазине — это **SpeakaBoo** (`adamId` вроде `6789069556`, в поиске
Appmagic `removed: true`). Приложение **снято с продажи**.

Обычный путь Apple (`volumeStore` / витрина) отвечает *No Longer Available*.
Файл всё ещё можно забрать из покупок ступенью **`ent/download`**, но ей нужно
подтверждение FairPlay — утилита **`kbsync`** (Unicorn + `assets.bin`).

На ПК, где `kbsync` живой и выход в интернет **домашний** (не VPN-датацентр),
та же учётка качает. На машине, где `kbsync` не стартовал **или** Apple видит
датацентровый IP, Signum пишет:

> Приложение снято с продажи в App Store. Apple не отдаёт файл даже владельцу
> лицензии, восстановить из покупок нельзя. Поможет только IPA, сохранённый
> раньше.
>
> `Download error: SpeakaBoo No Longer Ava [ent/download: не выполнен (нет kbsync)]`

Это **не** «учётка мёртвая» и **не** Node.js. Текст в UI врёт, если сломался
`kbsync` или VPN: с другой машины с тем же Apple ID файл есть.

**Два независимых стопора:**

1. **`kbsync` не собрал блоб** — чистая Windows 11 (целостность памяти, Smart
   App Control, Защитник, нет VC++), таймаут 25 с в билде 28.
2. **VPN / датацентровый IP** — Apple отвечает 403 на authenticate и не отдаёт
   снятое. Бывает клиент (sing-box, Elix) **и роутер с VPN**.

Сегодня на ноуте пользователя выход в Лондон — **VPN на роутере**, не баг
Signum. Этот ПК (Ярославль, Gorizont `46.16.29.1`) качает; ноут за тем же
Wi‑Fi, но наружу идёт **HOSTKEY, Лондон `89.125.212.45`**, потому что роутер
гонит трафик в VPN.

## 3. Исключение в Защитнике

Параметры → Конфиденциальность и защита → Безопасность Windows → Защита от
вирусов и угроз → Управление параметрами → **Исключения** → Добавить → **Папка**:

```
C:\Users\ИМЯ\AppData\Local\Signum
```

Имя — логин Windows. Быстрый путь в проводнике: `%LOCALAPPDATA%\Signum`.

По желанию ещё **Процесс**: `signum.exe`, `ipatool.exe`, `kbsync.exe`.

PowerShell от администратора:

```powershell
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\Signum"
Add-MpPreference -ExclusionProcess "signum.exe"
Add-MpPreference -ExclusionProcess "ipatool.exe"
Add-MpPreference -ExclusionProcess "kbsync.exe"
```

В установщике Signum исключения **пока нет**.

## 5. Как устроен `kbsync` (чтобы не путать с «нет в магазине»)

Код: `tmp-ipatool-cpp/appstore.cpp` `fetch_kbsync` / `try_ent_download`.

- Кеш: рядом с движком `kbsync.cache`, живёт **1800 с**.
- Список версий **не** генерирует kbsync (`allowGenerate=false`) — только горячий
  кеш. Генерация: скачивание и фоновый `warm-kbsync`.
- Нужны рядом: `kbsync.exe`, `libunicorn.dll`, `ucworker.dll`, плюс `assets.bin`
  и env **`SIGNUM_ASSET_KEY`** (Signum ставит потомку в `run_process_inner`).
- Импорты: `kbsync.exe` → `libunicorn.dll` + UCRT (`api-ms-win-crt-*`).
  `libunicorn.dll` → `KERNEL32` + `msvcrt`. Отдельный VC++ redist для unicorn
  не обязателен; UCRT на нормальной Win10/11 есть. Режет скорее HVCI / Smart
  App Control / Защитник / таймаут.

Лестница (из `README-18-9-26.md`):

```
1. ent/download без генерации kbsync
2. volumeStore
3. redownload
4. updateProduct
5. ent/download С генерацией   ← снятые с продажи
```

Прогрев: `warm_kbsync_cache` / `ensure_kbsync_warm` в `main.rs`.

## 10. Карта «чистое Windows 11 / не качает снятое»

Проверять по порядку:

1. Публичный IP — жилой, не hosting/VPN (ipinfo: `org`, city).
2. Сборка Signum ≥ **1.1.4.29** (таймаут 75 с).
3. Целостность памяти выкл **и перезагрузка**.
4. Smart App Control выкл.
5. Исключение Защитника на `%LOCALAPPDATA%\Signum`.
6. Рядом с `ipatool.exe`: kbsync, libunicorn, ucworker, assets.bin.
7. После входа — прогрев kbsync (есть `kbsync.cache` ненулевого размера).
8. Не слать в Telegram ожидаемое «нет в покупках / нет в App Store / подождите
   сменить страну». Обязательно слать: cookies unmarshal, illegal base64,
   failed to get account, вход/iCloud, установка, лимит App ID.
